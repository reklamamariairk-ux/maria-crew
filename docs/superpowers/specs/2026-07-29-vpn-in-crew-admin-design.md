# VPN в админке maria-crew (объединение с vpn-panel)

Дата: 2026-07-29. Утверждено владельцем (вариант A из брейншторма).

## Цель

Один интерфейс: сотрудники и их VPN-доступ ведутся в админке maria-crew.
Отдельная админка vpn-panel уходит со сцены (остаётся запасным входом),
список людей один — сотрудники crew.

## Архитектура

- **vpn-panel остаётся сервисом-движком** без изменений механики:
  users.json → ss-config.json → рестарт ss-multi, сторож шаринга,
  nft-счётчики, `/api/activate` + `/api/check` для Windows-клиентов,
  РФ-релей активации на Timeweb. Всё это не трогаем.
- **Новое в vpn-panel:** сервисный доступ — заголовок `X-Service-Token`
  со значением env `SERVICE_TOKEN` проходит auth наравне с cookie-сессией.
  Без env токен-доступ выключен (обратная совместимость).
- **crew** получает роуты `/api/vpn/*` (только superadmin), которые
  проксируют вызовы в vpn-panel: `VPN_PANEL_URL` (в проде
  `http://host.docker.internal:8090`, crew в bridge → host-gateway через
  `extra_hosts: host.docker.internal:host-gateway` в docker-compose),
  заголовок `X-Service-Token: $VPN_SERVICE_TOKEN`. Таймаут 8 с.

## Данные

Таблица в Postgres crew (новая миграция):

```sql
CREATE TABLE employee_vpn (
  employee_id INTEGER NOT NULL UNIQUE REFERENCES employees(id) ON DELETE CASCADE,
  vpn_name    TEXT    NOT NULL UNIQUE,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

- Маппинг «сотрудник ↔ имя в users.json панели». crew — источник правды
  по людям, vpn-panel — по ключам/портам; панель про crew не знает.
- Выдача нового доступа только из карточки сотрудника: crew вызывает
  `POST /api/users` панели с именем сотрудника (при коллизии имён —
  суффикс « (2)», « (3)»), затем пишет маппинг в той же операции.
- Переименование сотрудника в crew связь не ломает (vpn_name зафиксирован).

## API crew (`/api/vpn/*`, superadmin only)

- `GET /api/vpn/overview` — join: список пар (employee, vpn-user) c
  онлайном/трафиком/статусами/метками «передал» + список непривязанных
  vpn-юзеров + список сотрудников без VPN (для экрана связки).
- `POST /api/vpn/link` `{employeeId, vpnName}` — связать существующего.
- `POST /api/vpn/issue` `{employeeId}` — создать юзера в панели + связать;
  возвращает код активации + tgText.
- `GET /api/vpn/employee/:id` — detail карточки (проксирует
  `/api/users/:vpnName/detail`).
- `POST /api/vpn/employee/:id/:action` — прокси действий панели:
  `revoke | reactivate | reissue | unbind | phone | phone/revoke |
  phone/reactivate | phone/reissue`.
- Ошибки панели пробрасываются как есть; недоступность панели → 502
  `{error: 'vpn_engine_unavailable'}`.

## UI админки crew (стиль админки, tabAllowed)

- **Вкладка «VPN»** (только superadmin): таблица привязанных — сотрудник,
  точка, онлайн, трафик сегодня/всего, статус ПК, статус телефона, метки
  «Передал ключ»/«Код передавали»; клик — карточка сотрудника. Сверху —
  плашка «N VPN-юзеров не привязаны» + кнопка «Связать».
- **Экран/модалка связки** (разовая миграция): список непривязанных
  vpn-юзеров, к каждому селект сотрудников crew с подсказкой по совпадению
  имени; «Связать» по одному. Если человека нет в crew — создать сотрудника
  обычным путём и вернуться.
- **Карточка сотрудника, секция «VPN»**: нет связи → кнопка «Выдать VPN»;
  есть → код активации + TG-текст с предупреждением «1 устройство»,
  привязка ПК (+сброс), телефон (QR/выдать/отозвать/вернуть/перевыпустить),
  заметки «передал ключ/код» — та же информация, что была в панели.
- Вкладка видна/роуты доступны только superadmin: `tabAllowed` +
  server-side проверка роли (editor/coin_admin → 403).

## Отказы

- Панель недоступна: вкладка VPN показывает «VPN-движок недоступен»,
  кнопки в карточке disabled; никаких кешей/очередей управляющих действий.
- `issue` не атомарен между системами: сначала создаём юзера в панели,
  затем пишем маппинг; если маппинг упал — surfaced-ошибка, повторный
  `issue` видит существующего vpn-юзера с тем же именем и предлагает link
  (руками через экран связки). Ситуация крайняя, автоматики не строим.

## Тесты

- vpn-panel: X-Service-Token проходит auth; неверный/отсутствующий — 401;
  без env SERVICE_TOKEN токен-доступ выключен.
- crew: роли (editor/coin_admin → 403 на /api/vpn/*), link/issue пишут
  маппинг, повторный issue при существующей связи → 400, undefined
  action → 400, недоступность панели → 502.
- Живой прогон на проде: выдать тестовому сотруднику → активировать →
  отозвать → удалить.

## Вне скоупа

- Автосинхронизация увольнений (offboarding) — вручную через карточку.
- Перенос механики панели в crew (вариант B) — отвергнут.
- SSO между админками.
