# Увольнение сотрудников (+авто-отзыв VPN) — дизайн-спека

Дата: 2026-07-30. Запрос юзера: уволенный сотрудник (вручную или по пометке «не работает»
из 1С в имени) мгновенно теряет VPN без возможности выдачи, переезжает во вкладку
«Уволенные»; возврат в компанию — обратный перенос, «всё появляется обратно».

## Принятые решения (без вопросов, по правилу no-questions)

1. **Модель**: `employees.fired_at TIMESTAMPTZ NULL` (миграция 063). Уволен = `fired_at IS NOT NULL`.
   Увольнение также ставит `is_active=false` (начисления/напоминания выключаются существующей логикой);
   возврат — `fired_at=NULL, is_active=true`.
2. **VPN при увольнении**: по маппингу `employee_vpn` дергаем панель: `revoke` (ПК) + `phone/revoke`
   (телефон, если есть). Ошибки панели НЕ блокируют увольнение (панель может лежать) — результат
   отражаем в ответе (`vpn: ok|partial|unavailable`), админ видит и может повторить из карточки.
3. **Запрет выдачи уволенным**: `/api/vpn/issue`, `/issue-bulk` (пропуск с пометкой), `/link` → 403/skip
   `employee_fired`.
4. **Возврат**: `reactivate` + `phone/reactivate` тем же best-effort. Ключи в панели НЕ удаляются при
   увольнении (revoke закрывает порт, пароль сохраняется) — поэтому «всё появляется» без перевыдачи.
5. **Авто-увольнение по 1С-пометке**: при создании/переименовании сотрудника, если имя содержит
   `не работает` (регистронезависимо, гибкие пробелы) — авто-fire тем же флоу. Обратное переименование
   БЕЗ пометки автоматически НЕ возвращает (возврат — осознанная кнопка «Вернуть»).
6. **Доступ уволенного в Mini App/бот**: блок на аутентификации сотрудника (403 «уволен») — увольнение
   отключает не только VPN, но и вход в приложение команды. При возврате вход оживает сам.
7. **UI админки**: вкладка «Уволенные» в навигации (после «Сотрудники»), таблица: имя/точка/дата
   увольнения/VPN-статус + кнопка «Вернуть». Вкладка «Сотрудники» уволенных не показывает.
   В карточке сотрудника — кнопка «Уволить» (confirm), у уволенного — бейдж и «Вернуть».
8. **Роли**: увольнение/возврат — admin и superadmin (как редактирование), VPN-часть исполняется
   сервер-сайдом через сервисный токен (роль admin достаточна, /api/vpn/* остаётся superadmin-only).
9. **Аудит**: события `employee.fire` / `employee.restore` в существующий audit.service (кто/кого/когда,
   источник manual|auto_1c).

## Не делаем (YAGNI)

- Автовозврат по переименованию, отдельный экспорт уволенных, удаление ключей из панели,
  синхронизацию с 1С по расписанию (пометка ловится на входе имени в crew).

## Тесты

- Регекс пометки (варианты «(не работает)», «НЕ РАБОТАЕТ», лишние пробелы; отрицательные кейсы).
- fire/restore сервис с замоканной панелью: happy, panel down (fire проходит, vpn=unavailable), partial.
- Гейты: issue/link уволенному → 403, bulk пропускает, auth уволенного → 403.
- Авто-fire на create/update по имени.

## Деплой

Миграция 063 применяется автоматом при старте (migrate.ts). Обычный деплой crew на Hostinger,
прод-чек: fire→панель revoked→вкладка, restore→active.
